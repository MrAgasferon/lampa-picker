# Стенд для picker.js

Проверяет `picker.js` без телевизора и без сети: Node + jsdom + jQuery, мок Lampa, фейковые TMDB / CUB / Кинопоиск и виртуальное время. Весь набор проходит примерно за 2 секунды.

## Что внутри

```
test/
  env.js                окружение: jsdom, мок Lampa, сеть, IndexedDB, виртуальные часы
  checks.js             проверки (S* — базовое поведение, F* — находки аудита)
  run.js                запуск и итог
  known-failures.json   проверки, которые пока падают из-за неисправленных находок
  package.json          зависимости: jsdom, jquery, acorn
  package-lock.json
.github/workflows/test.yml   прогон в GitHub Actions на каждый push (проверяет picker-dev.js, если он есть, иначе picker.js)
```

## Запуск у себя

Нужен Node 18+.

```
cd test
npm install
npm test
```

Варианты:

```
node run.js --only S2,F1,F6a        # только эти проверки
node run.js --strict                # известные падения тоже считаются ошибкой
node run.js --json                  # итог одной строкой JSON
PICKER=/path/to/picker.js node run.js   # проверить другой файл (по умолчанию ../picker.js)
```

## Как читать результат

```
PASS   S2   Полный подбор: есть финалисты, первая страница из 5, без «Нравится» и истории
            → финал 30, страница 5, виденное в финале: нет
KNOWN  F1   Первый запуск: старые «Нравится» не считаются «пачкой»
            → пачкой помечено 12 из 12, вес лайка 0.6
```

- **PASS** — всё как должно быть.
- **KNOWN** — падает, но проверка числится в `known-failures.json`: это ещё не исправленная находка. Сборку не валит.
- **FIXED?** — проверка из `known-failures.json` вдруг проходит. Значит, находку исправили: уберите её ID из списка, и с этого момента проверка будет охранять исправление.
- **FAIL** — новое падение. Сборка красная: что-то сломалось или исправление сделано не так, как ждёт проверка.

Под каждой строкой `→` — что увидела проверка. Этого обычно хватает, чтобы понять, где искать.

На 0.11.4-dev: 60 PASS и 6 KNOWN (F22 — в переработке сериалов, остальное — P3).

## Рабочий цикл

1. Правите `picker.js`.
2. `npm test`, или просто загружаете файл на GitHub — Actions прогонит сам.
3. Исправленная находка показывает `FIXED?` — убираете её ID из `known-failures.json`.
4. Если что-то из уже работающего сломалось — будет `FAIL`.

## GitHub Actions при загрузке через браузер

Файлы стенда можно загрузить через «Add file → Upload files» вместе с папкой `test`. Папку `.github` проводник и Finder часто скрывают, поэтому workflow удобнее создать вручную: «Add file → Create new file», имя `.github/workflows/test.yml` (слэши GitHub сам превратит в папки), вставить содержимое файла из архива, «Commit».

После этого каждый push запускает проверки. Результат — значок у коммита и вкладка «Actions». Красный значок — есть `FAIL`.

GitHub Pages опубликует и папку `test` (она лежит в том же репозитории). Ничего секретного в ней нет, установку плагина это не затрагивает.

## Как это устроено

**Хук.** `picker.js` не меняется. В копию в памяти перед концом IIFE (`})()`) добавляется одна строка: она отдаёт внутренние функции в `window.__pk`. Список имён — массив `NAMES` в `env.js`. Если функцию переименовали или удалили, она приходит как `undefined`: стенд не падает, падает только проверка, которая её использует. При переименовании поправьте `NAMES` и проверку.

**Виртуальное время.** `setTimeout`, `setInterval` и `Date` внутри плагина подменены на часы стенда. Дедлайн КП в 5 с, страховка запроса в 17 с, квота на сутки — всё прокручивается мгновенно и одинаково при каждом запуске. Хелперы:
- `env.clock.advance(ms)` — прокрутить время;
- `env.cb(fn => …)` — вызвать функцию с колбэком и крутить время, пока колбэк не придёт;
- `env.run(answers)` — полный подбор, возвращает `{ st }`, `{ error }` или `{ timedOut }`;
- `env.profile()` — `collect → enrichEvents → buildProfile`.

**Мок Lampa.** `Storage` (включая `field` и `cache`), `Favorite`, `Timeline` (`view`, `link`, `watched` — по образцу `src/interaction/timeline.js` из lampa-source), `Utils.hash`, `TMDB`, `Reguest`, `Manifest`, `Controller`, `Noty`, `Activity`. Если плагин начнёт использовать что-то новое из `Lampa.*`, это нужно добавить в `makeEnv`.

**Сеть.** Все запросы идут через `Lampa.Reguest` мока в функцию-роутер. По умолчанию роутер изображает TMDB: discover, рекомендации, детали, коллекции. Своя сеть в проверке — параметр `router(url, params, def)`, где `def` — роутер по умолчанию. Ответ — `{ body }`, `{ status }`, `{ delay }` или `{ hang: true }` (запрос, который никогда не отвечает).

**IndexedDB.** `idb: 'fake'` — простая база с асинхронным `get` и снимком на момент запроса, как у транзакции, начатой раньше записи. `idb: { open() { return {}; } }` — база, которая не отвечает никогда. Без `idb` — IndexedDB нет, плагин работает на памяти.

## Где проверки опираются на выбранный способ исправления

Большинство проверок проверяют поведение, а не код. Но в нескольких пришлось выбрать договорённость; если исправите иначе — поправьте проверку:

| ID | Что ожидается |
| --- | --- |
| F4b | `PG-13` = 12+, то есть допустим в «С детьми» (как обещает плитка «до 12+»). Порог — ваше решение |
| F4d | в «С детьми» лучшее семейное выше триллера 12+ у любителя триллеров |
| F7a | `postReason` получает профиль (уже получает) и не считает мультфильм детским при `animShare` ≥ 0,3 |
| F9 | у заданий в `KpNet.queue` есть поле `url` |
| F11 | при недоступном TMDB вызывается `h.error(...)` или в состоянии есть `netError` / `netFail` / `offline` |
| F15 | используется поле `updated` из `Timeline.view()` |
| F21 | кешируются только `completed` и `empty`; есть ли у CUB другие статусы — не проверено |
| F22 | длительность серии — медиана `episode_run_time` |
| F30 | `Timeline.view` вызывается с `Timeline.link(card)` или используется `Timeline.watched` |

## Проверено ли, что проверки рабочие

Да. Каждая F-проверка падает на 0.10.3 ровно по описанной в аудите причине. На черновой копии `picker.js` с исправлениями (около 50 небольших правок по рецептам аудита) проходят все 43. Базовые S-проверки отдельно проверены на искусственно сломанных версиях: без возрастного фильтра падает S4, без фильтра длительности — S5, без исключения отказов — S3, без исключения «Нравится» и истории — S2.

## Чего стенд не проверяет

- Реальные телевизоры, вёрстку, фокус с пульта. В jsdom нет раскладки (все размеры нулевые), поэтому `sizeCards`, `ensureVisible` и навигация не тестируются.
- Реальные ответы TMDB, CUB и Кинопоиска — данные синтетические.
- Находки без проверки: F13 (ёмкость ключа КП — арифметика), F14 (приёмник `feedback.gs`, его нет в репозитории), F20 (лишние запросы после дедлайна — проще проверить вместе с F9), F26 (причина зависит от порядка ответов — нужна генерация разных порядков), F32 (прогрев — вопрос формулировки в README).

## Как добавить проверку

В `checks.js`, в массив `CHECKS`:

```js
{ id: 'S9', title: 'Что должно быть', fn: async () => {
  const env = makeEnv(baseWorld());               // или makeEnv({ fav, world, router, storage, ... })
  const r = await env.run({ time: 'any', mood: 'any', company: 'solo' });
  const n = r.st ? r.st.rest.length : 0;
  return { ok: n > 0, got: 'финал ' + n };        // ok — как должно быть; got — что увидели
} },
```

Если проверка про ещё не исправленную ошибку, добавьте её ID в `known-failures.json`.
