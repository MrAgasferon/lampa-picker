# Lampa Picker — техническая документация

Версия: 0.10.3 · Описание для пользователей — в [README.md](README.md). Подробная модель подбора с формулами и константами — в документе «Модель подбора — как работает».

## Принципы

- Всё работает на устройстве: нет своего сервера, нет LLM, нет телеметрии.
- Данные берутся из локальных данных Lampa (избранное, история, таймлайн), TMDB и метаданных CUB — тех же, что Lampa показывает в карточке фильма.
- Вкусы конкретного пользователя в код не вшиваются: пороги по годам, доля анимации и жанровые предпочтения считаются из данных.
- Чужие API-лимиты не тратим: ключ Кинопоиска из rating.js не используется.

## Установка

1. Плагин опубликован через GitHub Pages репозитория `mragasferon/lampa-picker`.
2. Lampa → Настройки → Расширения → Добавить плагин → `https://mragasferon.github.io/lampa-picker/picker.js`.
3. Перезапустить Lampa. В меню появятся пункт «Что посмотреть» и раздел настроек с тем же названием.

Версия видна на первом шаге мастера, на экране журнала, в настройках («Версия X.Y.Z») и в консоли: `LampaPicker.version`.

## Конвейер подбора

1. **Мастер:** время (до 40 мин / до 1,5 ч / до 2 ч / сериал на вечер / неважно) → настроение (расслабиться / посмеяться / пощекотать нервы / подумать / удиви меня / неважно) → компания (один / вдвоём / с детьми / компанией).
2. **Сигналы** (`collect`) из `Lampa.Favorite` и `Lampa.Timeline`:

   | Источник | Вес |
   | --- | --- |
   | like | 1 |
   | досмотрено (≥ 85% или ≤ 10 мин до конца) | 0,8 |
   | book, wath, look, scheduled | 0,4 |
   | history, continued | 0,3 |
   | thrown | −0,5 |
   | «Открыть» в выдаче | +0,5 |
   | «Не то» без причины или «Не интересно» | −0,2 |
   | «Не то» → «Не мой жанр» | −0,3 |
   | «Не то» → «Не под настроение», «Не для этой компании», «Слишком старое» | 0 (вкус не трогаем) |
   | «Уже видел» | 0 (только исключение) |

3. **Обогащение:** детали TMDB (ключевые слова, режиссёр, актёры) для 25 самых значимых событий.
4. **Профиль:** центрированные веса жанров, доля анимации (`animShare`), порог по годам (`yearFloor` — год, выше которого 90% веса событий; нужно не меньше 10 датированных событий; классика — рейтинг TMDB от 8,0 и старше 25 лет — в расчёт не идёт), seed-фильмы (s > 0,25, до 15).
5. **Пул кандидатов:**
   - `rec` — рекомендации TMDB по seed-фильмам, подходящим под настроение (до 5 при заданном времени, иначе до 8);
   - `disc` — discover по жанрам настроения;
   - `explore` — жанр с небольшим положительным весом;
   - `kw` — discover по 6 сильнейшим ключевым словам профиля (через «или», вес ≥ 0,3, нужно минимум 2), с фильтрами времени, годов и исключёнными жанрами настроения; причина — «Темы, как в ваших любимых фильмах»;
   - `ppl` — discover фильмов с 3 любимыми режиссёрами и 4 актёрами (`with_people` через «или»), рейтинг от 6,0; причина — «Режиссёр …» / «С …»;
   - `wath` — закладки «Позже».
6. **Префильтр → детали** пачками по 30, лимит 90 карточек (150 в строгих режимах: «до 40 мин» и «с детьми»).
   Не предлагаются: всё из истории Lampa, начатое (фильм — прогресс в таймлайне; сериал — `online_watched_last` или прогресс S1E1–E3, то есть и онлайн-просмотр мимо истории), «Уже видел», «Не то» за 90 дней, открытое из подборки за последние 3 дня (`opened`).
7. **Фильтры** (`postReason`): мало голосов, детский контент вне режима «С детьми», анимация для пары или компании при `animShare < 0,2`, возрастной рейтинг, длительность, отсутствие длительности и т. д. Причины отсева пишутся в журнал.
8. **Скоринг:**

   ```
   score = (wq·Q + wa·A' + wn·N + ws·S) / (1 − wm) × (0.15 + 0.85·M) × (0.3 + 0.7·F) × Y × D
   ```

   - Q — байесовский рейтинг TMDB (C = min(среднее по пулу, 6,0), m = 500 для фильмов и 200 для сериалов) плюс поправка по КП и IMDb (см. ниже);
   - A' — совпадение со вкусом, растянутое по текущему списку;
   - N — новизна; S — случайный сдвиг, привязанный к дате (в течение дня выдача стабильна);
   - M — соответствие настроению (множитель-«ворота»): 0,3 + 0,7 × лучший положительный вес жанра + сумма отрицательных весов (полностью), затем поправки по компании и шкалам CUB. Положительный вес жанра поправляется на вкус: жанр в профиле ≥ 0,2 — полностью, ≤ 0 — наполовину, между — линейно (при профиле от 10 событий);
   - N — новизна: незнакомый жанр даёт 0,6 только в «Удиви меня», в остальных настроениях 0,15;
   - F — формат (анимация); Y — фактор года;
   - D — нелюбимый жанр: если у фильма есть жанр с весом в профиле ≤ −0,6, ×0,6 (кроме «Позже»).

   Веса «Подумать»: фантастика, детектив, история 0,8; документальный 0,6; военный, драма 0,5; криминал 0,4; мелодрама −0,2; анимация, музыка, приключения −0,3; комедия, боевик −0,5; ужасы, семейный −0,8.

   Явные причины отказов корректируют профиль только при повторе:
   - «Не мой жанр»: жанр, который встретился в 2+ таких отказах, получает −0,3 за каждый отказ сверх первого;
   - «Слишком старое»: после 2+ отказов порог по годам — десятилетие после второго по свежести отвергнутого года (если он выше порога из истории).

9. **Франшизы:** одна франшиза — одна карточка (первая непросмотренная часть).
10. **Разнообразие:** MMR с λ = 0,7, в выдаче 5 карточек.

## Шкалы содержания (CUB)

Источник тот же, что у блока «Метаданные» и тегов настроения в карточке фильма Lampa:

```
{Lampa.Utils.protocol()}{Lampa.Manifest.cub_domain}/api/ai/video-view/{tmdb_id}/metadata?type=movie
```

- Ответ: `status` (`completed` / `empty`), `review: [{name, values[], avg}]` (avg 0–10: humor, violence, fear, tension, romance, sadness, pace, importance, action, sex, profanity), `moods: [{name, percent}]`.
- Только фильмы: для сериалов Lampa этот запрос не делает, и плагин тоже.
- Запрашивается после фильтров, для 20 лучших по предварительной оценке фильмов. Подбор ждёт не дольше 5 с (одновременно с КП), остальное берётся по жанрам.
- Отдельная очередь: 2 параллельных запроса, таймаут 5 с, без повторов, чтобы не занимать слоты TMDB и КП.
- Кеш: `completed` — 30 дней, `empty` — 7 дней, ошибки сети не кешируются.
- Выключается вместе с метаданными Lampa (`lampa_settings.disable_features.metadata`).

Как используются шкалы:
- 65% оценки настроения M (35% — веса жанров);
- `harshAdult`: насилие или страх ≥ 5;
- для режима «С детьми» повторная проверка после загрузки шкал: страх > 6, насилие > 5, лексика > 3 или откровенность > 2 — отсев (`kids_moods`);
- в описании фильма — четыре самые выраженные шкалы.

## Экран «Настроить вкус»

Сетка известных фильмов и сериалов для быстрой отметки «Нравится».

- Открывается кнопкой «Настроить вкус» на первом шаге мастера; сам — один раз, если в «Нравится», истории, закладках, «Позже» и «Просмотрено» вместе меньше 5 карточек (`picker_taste_offered`).
- Кандидаты: `movie/top_rated`, `tv/top_rated`, `movie/popular`, `tv/popular` (по странице каждого, вперемешку), от 1500 голосов, с постером, без дублей. По 24 за раз, «Ещё фильмы» — следующая порция.
- OK/тап ставит или снимает отметку: `Lampa.Favorite.add('like', card)` / `remove`. Уже отмеченное в «Нравится» показывается отмеченным (`Lampa.Favorite.check`).
- Логику подбора экран не меняет: плагин и так читает «Нравится» (+1,0) при каждом подборе.
- Пачка «Нравится» за один день (от 6 отметок — с этого экрана или вручную) при истории от 30 других событий сглаживается: такие события получают медианную дату истории (меньше «свежести»), вес 0,6 вместо 1,0 и занимают не больше 40% опорных фильмов (6 из 15). В журнале — `profile.likeBatch`.

## Причины «Не то»

После «Не то» открывается меню Lampa «Почему не то?»: не под настроение / не мой жанр / слишком старое / не для этой компании / не интересно / пропустить. «Назад» отменяет отказ. Любой выбор скрывает фильм на 90 дней. Причина хранится вместе с отказом (`fb.rejected[k].r`, а также настроение и компания в момент отказа) и пишется в журнал (`why`). В профиле журнала видно, что сработало: `rejGenres`, `yearFloorBy: 'rejects'`.

## Возрастные рейтинги

Приоритет у американского рейтинга (R, NC-17, TV-MA); российский 18+ используется, только если американского нет. `harshAdult` = R + жёсткий жанр (боевик, триллер, криминал, ужасы, военный) или шкалы насилия/страха ≥ 5. Такой контент штрафуется в настроениях «Расслабиться» и «Посмеяться» и в режиме «Вдвоём».

## КП и IMDb в оценке качества

Поправка к TMDB, а не замена: учитывается, насколько фильм на КП/IMDb лучше или хуже обычного при таком рейтинге TMDB.

```
d_kp   = КП − TMDB − смещение_КП
d_imdb = IMDb − TMDB − смещение_IMDb
corr   = ⅔·d_kp + ⅓·d_imdb   (одна оценка — берётся она; ни одной — 0), ограничено ±2,5
alpha  = 0,15 + 0,15 · m/(голоса + m)      (мало голосов на TMDB — больше доверия КП/IMDb)
       + 0,3 · свежесть · min(1, max(0, |corr| − 0,5))
         свежесть = (3000 − голоса)/3000 при голосах < 3000, иначе 0 — новинки на TMDB завышены первыми голосами
Q      = (взвешенный TMDB + alpha·corr − 5,5) / 3
```

- Смещения шкал считаются по собственному кешу (`kpmap` хранит и TMDB), сжаты к значениям по умолчанию: КП −0,2, IMDb +0,1, с весом 20 наблюдений.
- Оценки берутся из кеша для всех кандидатов, а для 20 лучших после ранжирования без оценки — запросом. Затем список переранжируется.
- Запросы идут от лучшего к худшему, по 3 фильма одновременно. Бюджет на один подбор: 12 запросов со встроенным ключом, 40 с личным. Оценки КП и шкалы CUB запрашиваются одновременно, подбор ждёт их не дольше 5 с.
- Со встроенным ключом плашки на карточках за пределами финалистов («Ещё варианты», дальние страницы) берутся только из кеша.
- Если КП заметно поднял фильм (поправка ≥ 0,15 пункта, КП ≥ 7,5), а более сильного объяснения нет, причина выбора — «Высоко на Кинопоиске: 8,4».
- В журнале по карточке: `kp`, `imdb`, `rsrc` (cache/net), `rc` (поправка в пунктах), `rb` (вклад в рейтинг); по подбору — `kp: {req, off, rated}`.

## Рейтинги КП и IMDb на карточках

Для показанных карточек, которых не было среди финалистов:

1. кеш rating.js `kp_rating` (если стоит);
2. собственный кеш `kpmap` (14 дней);
3. kinopoiskapiunofficial по imdb_id, запасной вариант — поиск по названию и году.

Найденное пишется и в `kp_rating`, чтобы rating.js не запрашивал повторно.

| Ключ | Лимит на устройство в сутки |
| --- | --- |
| Встроенный (обфусцирован в коде) | 40 запросов |
| Личный (Настройки → «Что посмотреть» → «Ключ Кинопоиска») | 200 запросов |

Отдельная очередь (3 запроса одновременно, таймаут 4,5 с, без повторов) не мешает TMDB. Два сетевых сбоя подряд — час только кеш (`diag().kp.offlineUntil`). Квота списывается в момент отправки. Счётчик привязан к ключу и сбрасывается ежедневно. Личный ключ при вводе проверяется пробным запросом. При 402/429 ключ блокируется до конца суток, на встроенном ключе это происходит без уведомления.

## Сеть и нагрузка на API

- TMDB вызывается через `Lampa.TMDB.api()`, поэтому используется прокси, настроенный у пользователя.
- Очередь: не больше 4 параллельных запросов. На 429 вся очередь встаёт на паузу 2 с × 2^n (до 3 повторов). Ошибки 4xx не повторяются, сеть и 5xx — один повтор через 1,5 с.
- Время жизни кеша: списки (рекомендации, discover) — 7 дней, детали — 30 дней.
- Прогрев: раз в сутки, через 30–120 с после старта, только при наличии IndexedDB. Подтягивает рекомендации по 8 seed-фильмам.

## Хранилище

| Что | Где |
| --- | --- |
| Кеш TMDB/КП/CUB | IndexedDB `lampa_picker`, store `kv`, записи `{t, v}` с TTL |
| Журнал, kpmap | IndexedDB (слой Durable, запись с задержкой 2 с, сброс на `pagehide`/`visibilitychange`) |
| Ответы, «Не то», «Уже видел», квота КП, ключ | `localStorage` с префиксом `picker_` (маленькие объекты) |

Старые `picker_journal` и `picker_kpmap` при первом запуске переносятся из `localStorage` в IndexedDB и удаляются. Лимит Lampa в 5 МБ не затрагивается.

## Журнал подборов

Локально хранятся последние 20 сессий: ответы, профиль, покрытие шкалами CUB (`cub: [получено, запрошено]`), статистика пула и отсева, показанные карточки с разбивкой Q/A/M/N/S и рейтингами, действия пользователя. Наружу журнал уходит только при ручном экспорте.

Экран «Журнал» (с первого шага мастера и снизу выдачи):

- **Скопировать журнал** — формат `LPJ2`: gzip + base64, последние сессии, сколько поместится в 3900 символов (одно сообщение мессенджера);
- **Последний подбор текстом** — читаемый вариант одной сессии;
- **Отправить автору** — весь журнал (`LPJ1`, gzip + base64) и необязательный комментарий уходят POST-запросом на Google Apps Script. Кнопка есть, только если в коде задан `FEEDBACK_URL`. Лимит — 5 отправок в сутки с устройства. Комментарий вводится клавиатурой Lampa: пустой ввод — отправка без комментария, «Назад» — отмена. Настройка приёмника — в [FEEDBACK.md](FEEDBACK.md), код — `feedback.gs`;
- **Поделиться** — системное меню, если устройство его поддерживает;
- **Очистить**.

Наружу журнал уходит только по кнопке: «Скопировать», «Поделиться» или «Отправить автору». Журнал на подбор не влияет. На подбор влияют сигналы «Открыть», «Не то» и «Уже видел», а они хранятся отдельно.

## Диагностика

```js
LampaPicker.diag()
```

| Поле | Норма | Если нет |
| --- | --- | --- |
| `version` | текущая версия | закешировалась старая — перезагрузить Lampa |
| `favorites.*` | числа > 0 при наличии данных | другие имена списков в сборке |
| `timelineSample` | объект с `percent` | прогресс не учитывается, подбор работает без него |
| `TMDB test` | `OK — <название>` | проблема с прокси или ключом TMDB |
| `kp` | `builtin`/`personal`, `today`, `blocked: false` | ключ упёрся в лимит или не прошёл проверку |
| `CUB metadata` | `OK` и шкалы «Матрицы» | CUB недоступен или выключен в сборке — работает оценка по жанрам |
| `idbOpened` | `true` | кеш живёт только до перезапуска |
| `localStorage` | отчёт по занятому объёму | — |

## Консоль

```js
LampaPicker.version         // версия
LampaPicker.debug(true)     // разбивка оценки под карточками + логи
LampaPicker.collect()       // события профиля
LampaPicker.journalFit()    // то, что копирует кнопка (LPJ2)
LampaPicker.journalLast()   // последний подбор текстом
LampaPicker.journal()       // весь журнал
LampaPicker.setKpKey('…')   // личный ключ КП ('' — удалить)
LampaPicker.reset()         // сбросить «Не то», «Уже видел» и последние ответы
```

## Ограничения

- Холодный старт: при истории меньше 5 фильмов подбор идёт по рейтингу и настроению, пока пользователь не отметит фильмы на экране «Настроить вкус».
- Прогресс сериалов по эпизодам не учитывается.
- Шкалы содержания есть только для фильмов и не для всех; сериалы оцениваются по жанрам.
- Нет настроек исключения жанров и выбора типа контента.
